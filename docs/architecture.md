# 设计与实现说明

本文描述当前版本的实现边界和生命周期。

## 1. 分层

- `SimulationPlan`、`MechanismSpec`、`TrackSpec`、`InstructionTape` 是不可变定义。
- `TrackNetwork` 在计划构造时把轨道编译成 `+/-` 查询，并验证轨道节点的唯一归属。
- `OrthogonalSimulator` 保存机构、棋盘、实体、抓取计数、周期和事务快照。
- `GlyphRuntime` 保存计划快照对应的符文实例状态、半周期视图和当前整数周期的延迟产物。
- `GlyphRegistry` 只负责类型定义注册；计划构造时解析并复制所引用的定义，之后注册表变化不影响计划。

项目不提供原子或键名称注册类。原子类型是调用方解释的 `int`，键类型是 `byte`，两者可以使用相同数值。

## 2. 轨道拓扑

`TrackSpec` 是不可变的有序节点列表与显式闭环标志，同一条轨道可自由混合正交和对角单位步。
`new TrackSpec(points)` 默认开放，`new TrackSpec(points, true)` 声明闭环。闭环至少包含三个不同节点，
末点到首点必须是一单位步；仅首尾相邻不会自动闭合。显式闭环输入末尾可重复一次起点，规范化后的
`points()` 不包含该次重复，其余重复节点及非单位步均拒绝。

`PLUS/MINUS` 分别沿节点声明顺序前进、反向后退，与机构朝向无关。开放端点无对应出口或机构
不在轨道上时，移动返回原地。单点轨道参与静态布局占位，不产生移动边。

不同轨道声明禁止共享任何格点，包括端点、内部节点、闭环节点和单点轨道；同一轨道重复声明也会
构成重叠。`TrackNetwork.from` 先按轨道声明顺序与节点顺序检查全部节点的唯一归属，再构建正反向
目标表。首次发现共享节点立即抛 `InvalidTrackOverlapException`；消息包含冲突坐标与两条
轨道从 `0` 开始的声明下标。线段可以在格子中心交叉，交叉处不建立连接。

空路径、重复节点、非单位步和非法闭环抛 `IllegalArgumentException`；坐标计算使用精确加减，
溢出抛 `ArithmeticException`。布局校验和渲染均消费规范化节点，闭合边由 `isLoop()` 决定。

## 3. 周期生命周期

每个整数周期包含两个半周期。两个半周期都执行下表阶段，只有第二半周期执行机构变换：

| 阶段 | 第一半周期 | 第二半周期 |
|---|---|---|
| Decode | 读取当前周期指令 | 读取同一周期指令 |
| Intent | `GRAB/RELEASE` | 移动、旋转、伸缩及携带实体；静止持有者提交 `STAY` |
| Conflict | 按实体检查意图兼容性 | 同左 |
| Transform | 不改变机构 | 写入 `next*` 暂存状态 |
| Deferred products | 重试上一阶段登记的产物 | 重试第一半周期登记的产物 |
| Runtime overlap | 无机构运动；实体目标仍检查 | 检查最终分子与分子、分子与机构基座、机构基座之间的重叠 |
| Commit | 提交实体、抓取计数和持有关系 | 再提交机构状态 |
| Produce | 输入模板生产 | 输入模板生产 |
| Glyph | 按声明顺序执行全部符文 | 按声明顺序执行全部符文 |
| Consume | 匹配输出并消费 | 匹配输出并消费 |

`cycle` 在两个半周期都成功或普通冲突停机后推进；符文异常和延迟产物运动冲突会回滚且不推进。
停机后 `step/run` 不再推进，`reset()` 才恢复。

### 3.1 事务范围

周期快照包含：机构位置/朝向/长度、棋盘原子、实体索引、抓取计数、持有关系、输出计数、
下一个实体 ID、符文实例状态和本整数周期的延迟产物。外部副作用（例如回调自行写文件）不在
模拟器事务范围内。

- 普通意图冲突、普通原子重叠和运行期重叠：记录警告、恢复快照、停机；不把控制异常暴露给调用方。
- 符文回调异常、延迟产物与运动冲突：记录警告、恢复快照、停机，并原样重抛异常。

## 4. 原子、键与分子

`Atom` 保存原子类型和四个方向的键字节：原子类型范围为 `0..0xFFFF`，
四方向键仍为 `byte`，按 `8 * direction.ordinal()` 打包在独立的 `int bondCodes` 中。
公开构造器、`Atom.of(int)`、`withType(int)` 和 `requireAtomCode(int)`
统一拒绝越界原子类型。双参数创建使用 `new Atom(int, int)` 还原类型与打包键。
键只有两条数值约定：

- 键字节 `0` 表示无键；
- 键字节 `0xFF` 表示临时键；其余非零键都是长期键。

原子类型在 `0..0xFFFF` 范围内有效，`AtomGrid` 用“格点不存在”表示没有原子。类型查询、计数、符文、运动和
输出匹配都使用完整的 `int` 类型；周期快照和回滚保存完整 `Atom` 对象。键类型不要求与原子类型
互异，也不要求名称存在。`MoleculeBfs` 默认只沿互惠长期键搜索；调用方可传入 `BondFilter`
把临时键纳入搜索。

测试编码辅助类仍保留调用方的 `byte` 编码体系，传入原子接口时自动扩宽；
调用方自己的保留码规则不限制引擎对类型 `0` 的支持，负字节不会被引擎转换为无符号类型。

## 5. 符文系统

`GlyphSpec` 声明类型 `typeId`、静态锚点和朝向；`GlyphDefinition` 定义占位、IO声明、状态工厂和行为。
符文、输入、输出分别按 `SimulationPlan.glyphs()`、`inputs()`、`outputs()`的声明顺序使用从 `0`
开始的下标。计划保存列表副本，下标只适用于当前计划，运行、整周期回滚和重置都保持各槽位对应的声明。
`SimulationPlan` 在构造时检查静态布局，冲突诊断使用 `glyph[n]`、`input[n]`、`output[n]` 标注实例及其冲突坐标。

`OrthogonalSimulator.glyphState(int glyphIndex)` 读取对应实例状态；回调使用
`GlyphContext.glyphIndex()` 获取自身在计划中的下标。输出计数通过 `outputCount(int outputIndex)`
读取，`outputCounts()` 返回按输出声明顺序排列的 `long[]` 副本；修改副本不影响模拟器，后续运行、
回滚和重置也不改变已返回的快照。符文状态及输出计数查询越界抛出 `IndexOutOfBoundsException`。

符文局部形状按朝东状态定义，`(0,0)` 是锚点，正 x 向东、正 y 向南；`GlyphSpec` 省略朝向时
默认 `EAST`。实例朝向决定绕锚点的旋转：`EAST` 为 `(x,y)`，`SOUTH` 为 `(-y,x)`，
`WEST` 为 `(-x,-y)`，`NORTH` 为 `(y,-x)`，再把世界偏移加到锚点上。
因此局部正 x 沿实例朝向，局部正 y 沿其右侧。占位、IO格点、行为和渲染统一委托
`Direction` 换算；逆变换中朝南与朝北互为逆旋转，朝东与朝西各自为自身的逆。
`GlyphContext.neighbor` 的方向参数以及输入槽的键方向仍按世界方向解释。

`GlyphReader` / `GlyphBoard` 的 `int placeholder` 是当前定义占位列表的 0-based 索引，
与 `glyphIndex()` 表示的计划内符文实例下标独立。
这是行为访问棋盘的唯一定位方式。输入和输出的 `position()` 也返回这个索引；定义构造时
检查范围、各自重复以及IO共享索引。越界抛出 `IndexOutOfBoundsException`，消息包含
索引、placeholder 数量和定义类型。空格点的 `entityAt(index)` 返回 `0L`，有效实体 ID 为正数 `long`。

上下文的 `worldPoint(index)` 先取当前定义的局部占位，再按实例朝向转为世界格点；
`neighbor(index, direction)` 沿世界方向取邻居。这两个上下文方法只接受占位索引；
`toLocal(GridPoint)` 继续用于世界坐标到局部坐标的逆变换。

### 5.1 回调窗口

每个半周期创建一个 `GlyphBoard` 视图，计划中的全部符文按声明顺序共用该视图。后一个符文
可以看到前一个符文已经提交的变更。每个符文执行输出检查、输入检查和行为之前，视图重新
绑定当前 `GlyphInstance`；相同索引分别使用各自的定义和朝向。所有读写先检查有效窗口、
当前绑定和索引范围，再解析世界格点。前置条件同样通过视图的索引 API 查询。
符文阶段结束后视图失效，任何读写方法（包括只读查询）都抛 `GlyphExecutionException`。

输入格点不匹配时整条符文跳过。输出格点被占用时整条符文在本整数周期的两个半周期都跳过。
所有输入槽都要求原子存在，`InputSlot.requiredAtomType` 用非 `null` 的 `OptionalInt` 独立表达类型约束：
为空时不限制类型，有值时精确匹配 `0..0xFFFF` 内的类型。
`occupied` 创建空类型约束；`of`、`bonded` 工厂及接收 `int` 类型的构造器均创建精确约束，拒绝负数和越界值。
完整构造器允许将空类型约束与键要求、自定义判据组合；原子不存在时直接跳过，不调用自定义判据。
跳过标记使用与符文实例数量等长的 `boolean[]`，按实例下标读写；每个周期开始、回滚和重置时
全部清零，同类型符文的标记相互独立。

### 5.2 写操作

`setType`、`spawn`、`queueSpawn`、`remove`、`bond`、`unbond` 都返回 `TryResult`：不满足
前置条件时返回 `SKIPPED`，不产生副作用；参数错误或失效视图才抛异常。

`bond` 的规则：缺少任一原子、任一侧有长期键（同键或异键）时跳过；只有单侧残留键或临时键
时覆盖并写入互惠键。`unbond` 只拆除互惠长期键，并在两侧写入 `0xFF`；下一个整数周期
开始清除临时键。带临时键或被抓取的原子不能被 `remove` 或输出消费。

方向键操作 `isBonded`、`bondedDirections`、`bond`、`unbond` 和 `wasJustUnbonded`
只允许邻居也在当前符文 placeholder 内：形状外读取返回 `false` 或不报告该方向，写操作返回
`SKIPPED`。`bondedDirections` 只报告形状内的长期键。`moleculeAt(index)` 仍返回从合法
占位原子开始的完整连通分子，但结果是不可变值，不能据此修改形状外原子。
`setType(int placeholder, int type)` 接受 `0..0xFFFF` 并保留实体 ID、键和抓取状态；
`spawn`、`queueSpawn` 同样接受类型 `0` 的原子。`remove` 仅允许删除存在、未抓取、不在机构持有集合中、
且没有长期键或临时键的原子；删除同时清理邻居反向键、位置和实体索引及抓取计数。

### 5.3 生产和延迟

`spawn` 在目标格空闲时立即落盘；目标格占用时登记延迟产物并返回 `SKIPPED`。`queueSpawn`
总是登记延迟产物并返回 `APPLIED`。登记立即占用目标格，后续符文和输入生产均可见。

延迟产物只在当前整数周期的两个半周期内重试：第一半周期登记的产物在第二半周期运动后
重试；第二半周期结束仍未落盘的产物被丢弃，不跨周期等待。产物不会覆盖原子；机构或实体
运动落到预留格点或本半周期刚落盘的产物格点时抛 `GlyphExecutionException` 并回滚整个周期。

## 6. 运行期重叠

这不是变换过程中的实时碰撞采样，也不记录碰撞统计。每周期在第二半周期变换结束、落盘前
检查最终状态：

- 两个不同实体不能占据同一格；
- 任一实体不能占据任一机构的最终基座格点。
- 两个机构不能占据同一最终基座格点；初始基座重叠也会在计划构造时被拒绝。

冲突记录警告并按普通事务规则回滚停机。机构在同一周期交换位置是合法的，只检查最终
格点，不采样移动路径。机构不设置 ID，按计划声明顺序使用从 `0` 开始的列表下标；
下标在当前计划内保持稳定，运行、回滚和重置均不改变其对应关系。通过 `mechanism(index)` 或 `mechanisms()` 查询机构的只读状态值，使用 `heldEntities(index)` 查询该机构持有的实体。

## 7. 范围边界

包含：无限正交网格、四向机构、混合正交与对角步进的轨道、半周期指令、实体意图、输入输出、静态符文、

不包含：导管、聚合物、生产柜、碰撞路径采样和碰撞统计，以及原子/键名称语义。
